# Developer Toolbox — Comprehensive Audit & Optimization Plan

## Project Overview
- **Stack:** React 19 + TypeScript + Vite 5.4 + Tailwind CSS v4 + react-router-dom v7
- **Type:** Client-side SPA with 40 developer utility tools
- **63 source files**, no backend, no tests, no linting

## Phase 1: Critical Bugs & Correctness Fixes

### 1.1 IP Lookup uses `useState` for side effects (BUG)
- **File:** `src/tools/ip-lookup/page.tsx:35`
- **Issue:** `useState(() => { getLocalIp(); getPublicIp(); })` — uses `useState` as an initializer for side effects. This is incorrect React usage. Should be `useEffect`.
- **Fix:** Replace with `useEffect(() => { getLocalIp(); getPublicIp(); }, [])` and add `useEffect` import.

### 1.2 Theme Toggle desyncs from CSS classes
- **File:** `src/components/layout/header.tsx:58-67`
- **Issue:** `ThemeToggle` manages theme via `useState("dark")` + `document.documentElement.setAttribute("data-theme", next)` + toggling `dark` class. But the CSS in `index.css:32` uses `[data-theme="light"]` selector, not `dark` class. The `dark` class toggle on `<html>` is from the initial `index.html` but the CSS never uses `.dark` — the theme variables only respond to `data-theme="light"`. This means toggling "light" correctly removes dark overrides, but toggling back to "dark" doesn't actually restore dark variables — it only re-adds the `dark` class which does nothing.
- **Fix:** Simplify theme toggle to only use `data-theme` attribute. When dark, remove `data-theme="light"`. When light, set `data-theme="light"`. Remove the `dark` class manipulation. Also persist theme preference to `localStorage` and read it on mount to avoid flash.

### 1.3 Theme state not persisted / no flash prevention
- **File:** `src/components/layout/header.tsx:59`
- **Issue:** Theme preference is lost on page reload. User always gets dark mode regardless of their choice.
- **Fix:** Read initial theme from `localStorage`, write to `localStorage` on toggle. Add a tiny inline `<script>` in `index.html` to set the correct class before React mounts to prevent FOUC (flash of unstyled content).

### 1.4 Duplicate `jwt-debugger` and `jwt-decoder` slugs
- **File:** `src/ToolPage.tsx:12,35`
- **Issue:** Both `"jwt-debugger"` and `"jwt-decoder"` map to the same lazy module. The slug in `constants.ts` is `"jwt-debugger"` but `ToolPage.tsx` also has a separate entry for `"jwt-decoder"`. If a user navigates to `/tools/jwt-debugger` it works; `/tools/jwt-decoder` also works (different slug, same component). But there's only ONE entry in `constants.ts` (slug: `"jwt-debugger"`), so `/tools/jwt-decoder` shows a 404 page since `getToolBySlug("jwt-decoder")` returns undefined.
- **Fix:** Remove the duplicate `"jwt-decoder"` entry from `toolModules` in `ToolPage.tsx` (keep only `"jwt-debugger"`), or align the slug in `constants.ts` to match. The cleanest fix is to ensure all 40 tools in `constants.ts` have matching entries in `toolModules`.

### 1.5 Missing `cron-parser` in constants.ts
- **File:** `src/lib/constants.ts`
- **Issue:** `cron-parser` tool has a lazy import in `ToolPage.tsx:45` and a directory `src/tools/cron-parser/page.tsx`, but it's NOT listed in the `tools` array in `constants.ts`. This means it won't appear in the dashboard, sidebar, or command palette — it's unreachable.
- **Fix:** Add the cron-parser tool definition to `constants.ts`.

### 1.6 X.509 Decoder is fake — always returns hardcoded data
- **File:** `src/tools/x509-decoder/page.tsx:14-31`
- **Issue:** `decodePEM()` ignores the actual PEM content and always returns hardcoded values (Subject: CN=localhost, Issuer: CN=localhost, etc.). The tool does not actually decode certificates.
- **Fix:** Install `pkijs` + `asn1js` + `pvutils` dependencies. Implement real X.509 certificate parsing using the PKI.js library:
  - Parse PEM → DER (base64 decode)
  - Use `pkijs.Certificate.fromBER()` to parse the DER
  - Extract Subject, Issuer (as formatted strings from `pkcs9.Name`), Serial Number, Validity (Not Before/After), Signature Algorithm, Key Size, SANs (from SubjectAltName extension), and Certificate Status (expired/valid)
  - Show raw hex data as a bonus tab

### 1.7 Code Assistant is not AI-powered despite description
- **File:** `src/tools/code-assistant/page.tsx` + `constants.ts:39`
- **Issue:** Description says "AI-powered code analysis" but it uses static rule-based checks, not AI.
- **Fix:** Update description to "Static code analysis with improvement suggestions" to set correct expectations.

### 1.8 `useEffect` dependency missing in `qr-generator`
- **File:** `src/tools/qr-generator/page.tsx:32-36`
- **Issue:** `useEffect` references `getQrText()` which depends on `type`, `ssid`, `password`, `email`, `subject` but the `useEffect` only depends on `[text, fgColor, bgColor, size, type, ssid, password, email, subject]` — actually this looks correct. However, `getQrText` is defined inside the component and changes every render. The `useEffect` should include it in deps or memoize it.
- **Fix:** Wrap `getQrText` in `useCallback` or move the QR generation into a separate `useEffect` that depends on all the relevant state values directly.

### 1.9 `useEffect` dependency issue in `jwt-decoder`
- **File:** `src/tools/jwt-decoder/page.tsx:41-45`
- **Issue:** `getTimeRemaining(decoded!.payload.exp as number)` — the `!` assertion could NPE if `decoded` changes state between render and effect execution.
- **Fix:** Add optional chaining or guard: `if (decoded?.payload && typeof decoded.payload.exp === "number")` — actually this is already done. The issue is the non-null assertion inside the update function: `decoded!.payload.exp` — should be safe since the outer check already guards, but could use `decoded?.payload?.exp` for safety.

## Phase 2: Accessibility (A11y) Fixes

### 2.1 Missing `lang` attribute persistence
- **File:** `index.html:2`
- **Issue:** `lang="en"` is set, which is good. But no `dir` attribute for potential RTL support.

### 2.2 Missing skip-to-content link
- **Issue:** No skip navigation link for keyboard users to bypass the sidebar and header.
- **Fix:** Add a visually-hidden skip link as the first focusable element in `App.tsx` that links to `<main>`.

### 2.3 Sidebar not keyboard-navigable
- **File:** `src/components/layout/sidebar.tsx`
- **Issue:** Category toggle buttons don't have proper `aria-expanded` attributes. Tool links lack `aria-current="page"` for active state.
- **Fix:** Add `aria-expanded={isOpen}` to category buttons and `aria-current={active ? "page" : undefined}` to tool links.

### 2.4 Command palette missing ARIA attributes
- **File:** `src/components/layout/command-palette.tsx`
- **Issue:** The backdrop `<div>` has no `aria-hidden` or screen reader text. `cmdk` handles most ARIA, but the custom overlay structure may not be fully accessible.
- **Fix:** Ensure `cmdk` Dialog handles focus trapping (it does by default). Add `aria-label` to the dialog.

### 2.5 Color picker eyedropper button has no accessible label
- **File:** `src/tools/color-picker/page.tsx:52`
- **Issue:** The Eyedropper button only has icon, no text. It has no `aria-label`.
- **Fix:** Add `aria-label="Pick color with eyedropper"` to the button.

### 2.6 Hash generator algorithm badges used as toggle buttons
- **File:** `src/tools/hash-generator/page.tsx:52`
- **Issue:** `<Badge>` with `onClick` is not semantically a button. Missing `role="button"` and keyboard handlers.
- **Fix:** Use `<Button>` instead of `<Badge>` for interactive elements, or add proper ARIA attributes.

### 2.7 Many form inputs missing labels
- **Issue:** Multiple tools use `<Input>` and `<Textarea>` without associated `<Label>` elements. While some have visual labels nearby, they're not programmatically associated via `htmlFor`/`id`.
- **Fix:** Add `id` to inputs and `htmlFor` to labels across all tool pages.

### 2.8 Missing `prefers-reduced-motion` support
- **File:** `src/index.css`
- **Issue:** All CSS animations (fade-in, float, pulse-glow, aurora, gradient-shift, slide-up) run unconditionally. Users who prefer reduced motion get all animations.
- **Fix:** Add `@media (prefers-reduced-motion: reduce)` that disables or reduces all animations.

### 2.9 Missing focus-visible styles on some interactive elements
- **Issue:** Some elements like the sidebar filter input, sidebar category toggle buttons use native focus styles that may not be visible in dark mode.
- **Fix:** Ensure all interactive elements have visible `focus-visible:ring` or `focus-visible:outline` styles.

## Phase 4: Performance Optimizations

### 4.1 Remove unused dependencies
- **Files:** `package.json`
- **Issues:**
  - `framer-motion` — installed but never imported. Remove.
  - `idb` — installed but never imported. Remove.
  - `date-fns-tz` — imported in timestamp-converter but timezone functions not actively used. Verify and potentially remove.
- **Fix:** Run `npm uninstall framer-motion idb date-fns-tz` (after verifying date-fns-tz usage).

### 4.2 Remove `"use client"` directives
- **Files:** All `.tsx` files in `src/`
- **Issue:** `"use client"` is a Next.js App Router convention. This is a Vite/React SPA — these directives are meaningless noise.
- **Fix:** Remove all `"use client"` directives from every file.

### 4.3 Optimize `command-palette.tsx` icon import
- **File:** `src/components/layout/command-palette.tsx:7`
- **Issue:** `import * as Icons from "lucide-react"` imports ALL ~1500 lucide icons into the bundle. This is a massive bundle bloat.
- **Fix:** Use the consolidated shared `iconMap` from `src/lib/utils.ts` (see 5.1). Import only `Home` and `Code` directly for the fallback, and use the shared map for tool icons.

### 4.4 Optimize `tool-page-header.tsx` icon import
- **File:** `src/components/shared/tool-page-header.tsx:4`
- **Issue:** Same as above — `import * as Icons from "lucide-react"` imports everything.
- **Fix:** Use the consolidated shared `iconMap` from `src/lib/utils.ts` (see 5.1).

### 4.5 Memoize expensive computations
- **Files:** `src/Dashboard.tsx:50-51`
- **Issue:** `filtered` and `grouped` arrays are recomputed on every render (including all tool card animations). With 40 tools, this is fine, but could be memoized.
- **Fix:** Wrap in `useMemo` with `[search]` dependency.

### 4.6 Dashboard hero word rotation — memory leak potential
- **File:** `src/Dashboard.tsx:42-48`
- **Issue:** `setTimeout` inside `setInterval` creates a nested timer. If the component unmounts during the 300ms timeout, the inner `setTimeout` will fire after unmount.
- **Fix:** Store the inner timeout ref and clear it in the cleanup function.

### 4.7 Debounce search inputs
- **Files:** `src/Dashboard.tsx:100`, `src/components/layout/sidebar.tsx:62`
- **Issue:** Search filtering runs on every keystroke. While 40 tools is small, it's a good practice.
- **Fix:** Add a small debounce (100-150ms) to search inputs, or leave as-is since the dataset is tiny.

### 4.8 Lazy-load highlight.js
- **File:** `src/tools/markdown-preview/page.tsx:9`
- **Issue:** `highlight.js` is imported eagerly but only used in markdown preview. It's a ~40KB library.
- **Fix:** Dynamic import it only when markdown preview is used.

## Phase 5: Code Quality & Maintainability

### 5.1 Consolidate duplicated `iconMap` definitions

## Phase 7: Security Hardening

### 7.1 HTML Preview iframe security
- **File:** `src/tools/html-preview/page.tsx:53`
- **Issue:** `sandbox="allow-scripts"` allows JavaScript execution in the iframe. While this is intentional (it's a code preview tool), it could be used for XSS if the tool URL is shared with malicious HTML.
- **Status:** Acceptable — this is the point of the tool. The `sandbox` attribute prevents the iframe from accessing the parent page.

### 7.2 Markdown Preview XSS prevention
- **File:** `src/tools/markdown-preview/page.tsx:53`
- **Issue:** Uses `DOMPurify.sanitize()` which is correct. Good.
- **Status:** Secure.

### 7.3 SQL injection in Mock Generator
- **File:** `src/tools/mock-generator/page.tsx:60`
- **Issue:** SQL INSERT generation uses string interpolation: `` `'${v}'` ``. If mock data contains single quotes, the SQL will break. However, since this generates mock data (not executes it), the risk is low — but it produces invalid SQL.
- **Fix:** Escape single quotes in string values: `v.replace(/'/g, "''")`.

### 7.4 Content Security Policy
- **Issue:** No CSP headers configured. The Vite dev server doesn't set CSP. For production, CSP should be configured via server headers or meta tag.
- **Fix:** Add a `<meta http-equiv="Content-Security-Policy">` tag in `index.html` with appropriate directives for the SPA.
